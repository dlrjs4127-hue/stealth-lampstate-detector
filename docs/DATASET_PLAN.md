### 규모 판단 근거(우리 실험)
| 실험 | 학습 규모 | 검증 mAP50 | 실제 프레임 결과 |
|---|---|---|---|
| 완전 생성 장면 | 59장 | 0.782 | 소등 후보 다수 오탐(표지판) |
| 12장면 라벨셋 | 120장 | 0.543 | 후보 28건 |
| ITS 합성(1클래스) | 58장 | 0.995 | 검출 0(과적합) |
| ITS 합성(2클래스) | 58 + 실프레임 51 | 0.961 | 정상 131 · 스텔스 0 |
| ROI 편집 합성 | 50 + 실프레임 51 | 0.976 | 정상 116 · 스텔스 0 |
| **ROI 편집 합성(현재)** | **144 + 실프레임 51** | 진행 | 진행 |

- 소형 객체(폭 중앙값 **50px**, 18~110px)라 클래스당 **300 인스턴스** 이상이 안정적입니다. 현재 stealth 인스턴스는 144개 수준 → **200~300장까지 확장**이 필요합니다.
- 반대로 상태 판정(점등/소등)은 실제 대응쌍 628쌍이 이미 있어 분류 단계에서 커버됩니다. 그래서 데이터를 **검출용(합성 확장)** 과 **상태 판정용(실제 대응쌍)** 으로 나눠 확보합니다.

## 2. 목표 규모(2026-12-18 기준)

| 구분 | 목표 | 현재 | 확보 방법 |
|---|---|---|---|
| 합성 스텔스(검출) | 300장 | 144장 | ROI 편집 반복(차종·조도·거리 변형) |
| 실제 정상 차량 | 1,200 인스턴스 | ~900(의사 라벨) | 실제 프레임 자동 검출 + 육안 확인 |

| 테스트(실제) | 60프레임/3사이트 | 51프레임 | 학습에 안 쓴 프레임 고정 |

## 3. 라벨 규칙
- `on`(점등 확인) / `off`(소등 확인) / `unknown`(판독 불가 → 학습·평가 제외)
- 합성 라벨: stealth 1대의 BBOX + 주변 실제 차량은 normal(자동 후보, IoU 0.15 이상 겹치면 제외)
- 형식: `frame, vehicle_id, x1, y1, x2, y2, state` (CSV), YOLO txt는 학습용으로 파생

## 4. 분할 규칙
- **장면(카메라+시간대) 단위** 60/20/20. 같은 클립의 연속 프레임이 train/val/test에 섞이지 않게 합니다.
- 합성은 **train에만**, 검증·테스트는 실제 프레임만 사용합니다.
- 테스트는 1회 개봉 원칙. 튜닝은 검증에서만.

## 5. 품질 관리
- 합성 검증: ROI 밖 픽셀 변경 0(전 장), 차량 BBOX 자동 검출 성공률(현재 94/112 = 84%), seam/밝기비 기록
- 실제 라벨: 자동 검출 → 육안 확인 2단계, 10% 구간 2회 라벨링으로 Cohen's kappa(목표 0.8)
- 버전: `scene112_manifest.json`, `roi_meta.json` 등 manifest를 저장소 `results/`에 커밋
