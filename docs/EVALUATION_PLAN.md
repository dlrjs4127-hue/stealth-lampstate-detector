# 평가 계획 (Evaluation Plan)

"무엇을, 어떤 데이터로, 어떤 숫자로 판단할 것인가"를 미리 고정합니다.
실험 후에 기준을 바꾸지 않기 위해 판정 기준은 실험 전에 적고 그대로 씁니다.

## 1. 판단 단위

| 단위 | 정의 | 쓰는 지표 |
|---|---|---|
| 차량(객체) | 한 프레임 안 차량 1대 (BBOX + 상태) | 검출 정밀도·재현율, 상태 판정 F1 |
| 프레임 | CCTV 정지 영상 1장 | 프레임당 오탐 수, 처리 지연 |
| 장면(카메라·시간대) | 같은 카메라의 연속 구간 | 분할 단위, 일반화 검증 |
| 영상(클립) | 촬영 1회분 | 클립 단위 재현율, 알림 빈도 |

- 학습/검증/테스트 분리는 **장면 단위**로 합니다. 같은 클립의 연속 프레임이 train과 test에 나뉘면 성능이 부풀려집니다.
- 테스트 세트는 **한 번만** 엽니다. 튜닝은 검증 세트에서만 합니다.

## 2. 데이터셋 계획

### 2.1 구성 목표

| 구분 | 내용 | 목표 규모 | 현재 |
|---|---|---|---|
| 실제 정상 차량 | 점등이 명확한 실제 CCTV 차량 | 800대 | 131~186대/51프레임(자동 라벨) |
| 실제 소등 차량 | 사람이 확인한 소등 차량 (핵심) | 300대 | **0대** |
| 합성 소등 차량 | 실제 프레임 배경 + 생성 차량(조도 변형 포함) | 600장(장면 100 × 6조도) | 58장 × 7변형 = 406장 |
| 판독 불가(UNKNOWN) | 램프 확인이 어려운 차량 | 별도 보관 | 분류 중 |

### 2.2 라벨 규칙

- **ON**: 전조등 또는 후미등 점등이 픽셀에서 확인됨
- **OFF**: 점등 흔적이 없고 차체 형태가 확인됨(그림자와 구분)
- **UNKNOWN**: 흐림·가림·원거리로 판독 불가 → 학습·평가 모두 제외
- 라벨 파일 형식: `frame, vehicle_id, x1, y1, x2, y2, state, note` (CSV). 같은 차량은 프레임이 달라도 `vehicle_id`를 유지합니다.

### 2.3 라벨 품질

- 자동 검출 후 육안 확인 2단계로 라벨을 만들고, 일부 구간은 두 번 라벨링해 **Cohen's kappa**를 기록합니다(목표 κ ≥ 0.8).
- 불일치 건은 `docs/EXPERIMENT_LOG.md`에 사유와 함께 남깁니다.

### 2.4 분할

- 장면 단위 60/20/20(train/val/test). 카메라·시간대가 겹치지 않게 배치합니다.
- 테스트 장면은 최소 3개 사이트(교량·IC·터널 출구 등)를 포함합니다.
- 합성 이미지는 **train에만** 사용하고, 검증·테스트는 실제 프레임만 씁니다.

## 3. 지표 정의

### 3.1 검출 성능(차량 상자)
- **mAP50 / mAP50-95**: Ultralytics 정의(IoU 0.5 / 0.5:0.95 평균)
- **Precision / Recall** @ conf 0.25·0.40·0.60
- **F1** = 2PR/(P+R)

### 3.2 상태 판정 성능(정상 vs 소등)
- **Recall(소등)** = 맞춘 소등 / 전체 소등 ← 가장 중요
- **Precision(소등)** = 맞춘 소등 / 소등이라고 표시한 것
- **Balanced accuracy** = (소등 재현율 + 정상 재현율)/2
- **F1(소등)**

### 3.3 운영 지표
- **FP/frame** = 잘못 소등으로 표시한 차량 수 / 프레임 수
- **시간당 알림 수** = CCTV 1대 기준 1시간 알림 수(검토 부담)
- **처리 지연(ms/frame)** = 검출 + 상태 판정 합계 (GPU / CPU 각각)

### 3.4 불확실성
- 테스트 규모가 작으므로 재현율은 **Wilson 95% 구간**을 함께 적습니다.
- 예: 소등 10대 중 6대 검출 → 재현율 0.60 [0.31, 0.83]

## 4. 판정 기준(실험 전 고정)

| 단계 | 지표 | 기준 | 미달 시 조치 |
|---|---|---|---|
| 파일럿 통과 | 소등 재현율(실제 테스트) | ≥ 0.50 | 합성 데이터 구성 재설계 |
| 파일럿 통과 | FP/frame | ≤ 1.0 | 임계값 상향·후처리 추가 |
| 파일럿 통과 | 처리 지연 | ≤ 50 ms/frame(GPU) | 입력 해상도·모델 축소 |
| 최종 목표 | 소등 재현율 | ≥ 0.70 | 생성 모델 교체 또는 실제 라벨 확대 |
| 최종 목표 | 소등 정밀도 | ≥ 0.60 | 상태 판정 단계 재학습 |
| 최종 목표 | mAP50(실제 테스트) | ≥ 0.60 | 검출 단계 재설계 |

> 합성 검증셋 성능(mAP50 0.9 이상)은 판정에 쓰지 않습니다. 판정은 실제 테스트 성능으로만 합니다.

## 5. 실험 매트릭스(11/21 ~ 12/11)

| # | 조건 | 학습 데이터 | 확인할 것 |
|---|---|---|---|
| E1 | 합성 단독 | 합성 600장 | 합성만으로 실제 소등을 잡는가 |
| E2 | 합성 + 실제 ON/OFF 혼합 | E1 + 실제 대응쌍 | 상태 판정 신호가 살아나는가 |
| E3 | 합성 + 실제 소등 라벨 | E1 + 실제 소등 300대 | 실제 라벨이 얼마나 필요한가 |
| E4 | 2단계(검출→상태판정) | E3 구조 | 오탐·지연이 기준 안에 드는가 |

- 네 조건 모두 같은 테스트 세트로 평가하고 `results/metrics_summary.md`에 누적합니다.
- 조건 비교는 재현율·FP/frame 두 축, 지연은 참고값으로 봅니다.
